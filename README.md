# RepoGuideAI

RepoGuideAI is an open-source onboarding workspace for public GitHub repositories. It retrieves real GitHub metadata, README content, files, and open issues, then provides optional repository-grounded guidance through a configured Gemma model.

> This project has no bundled service credentials. Repository browsing works without signing in. AI, accounts, and cross-device persistence require the server-side configuration described below.

## Features

- Analyze a public `github.com/owner/repository` URL without an account.
- Review GitHub repository metadata, language statistics, README, and root structure.
- Browse folders and retrieve text files on demand (250 KB preview limit).
- Search and filter real open GitHub issues. Beginner difficulty is only estimated from issue labels.
- Ask a repository-grounded assistant and generate a contribution roadmap using local Ollama/Gemma or a configured hosted inference provider.
- Track a contribution checklist locally or persist it to a user account.
- Register and sign in; save repositories and learning preferences in MongoDB.
- Responsive editorial interface, keyboard-accessible controls, and light/dark themes.
- REST API with URL validation, request limits, rate limiting, secure cookies, and server-only provider credentials.

The app never executes repository code and never creates issues, branches, or pull requests on GitHub.

## Architecture

```text
client/src/              React + TypeScript + Vite single-page application
server/index.js          Express REST API, auth/session and error handling
server/services/github.js  GitHub API retrieval and safe file decoding
server/services/ai.js      Google Gemma / OpenAI-compatible model adapter
server/models.js         Mongoose user, saved repository, and progress models
```

The GitHub integration only contacts `api.github.com` after validating a repository URL. README and source content are treated as untrusted data. AI answers are generated by the configured provider; the application does not substitute canned responses when credentials are missing.

## Requirements

- Node.js 20 or newer
- npm
- MongoDB (local Community Server or a MongoDB Atlas cluster) for accounts and cross-device storage
- Optional: GitHub personal access token to increase GitHub REST API limits
- Optional: Google AI Studio API key with access to the selected Gemma model, or a compatible local inference server

## Local development

1. Install packages:

   ```sh
   npm install
   ```

2. Copy `.env.example` to `.env` and set the values you need. Do not commit `.env`.

3. Start MongoDB if you want registration, saved repositories, and server-persisted progress. For example, configure `MONGODB_URI` for a local MongoDB service or an Atlas connection string.

4. Start the Vite client and Express API together:

   ```sh
   npm run dev
   ```

5. Open <http://localhost:5173>. The Vite development server proxies `/api` requests to `http://localhost:4000`.

Useful commands:

```sh
npm test
npm run build
npm start
```

`npm start` serves the API and, after a production build, the static frontend on the same port.

### GitHub API access and rate limits

Anonymous public REST API requests have a lower per-hour limit than authenticated requests. A fine-grained GitHub personal access token with public repository read access may be added as `GITHUB_TOKEN` on the server. For local development, copy `.env.example` to `.env`, set `GITHUB_TOKEN=your_token` in the root `.env`, then restart `npm run dev`. Create a fine-grained token with read-only access to public repository contents and issues. The application sends it only to GitHub from the backend. Never paste the token into the browser or commit `.env`. The server explains rate-limit responses and the reset time; retrying repeatedly does not bypass GitHub limits.

### Ollama and Gemma

Local Ollama is the default AI provider. Install [Ollama](https://ollama.com/download), start its service, and download the configured model:

```sh
ollama pull gemma3:1b
```

The API sends grounded conversation messages to Ollama's native `/api/chat` endpoint. Configure `OLLAMA_BASE_URL` and `OLLAMA_MODEL` if your Ollama server or model name differs. Ollama may take longer on the first request while loading the model; RepoGuideAI allows up to two minutes. An uninstalled model is reported with the exact `ollama pull` command rather than replaced with a canned response.

For an Ollama server on another host or in a container, set `OLLAMA_BASE_URL` to a URL that the backend can reach. Ollama's default service is not authentication-protected; do not expose it to the public internet without adding an authenticated private network or gateway.

You can instead select hosted inference with `AI_PROVIDER=google`, `GEMMA_MODEL`, and `GEMMA_API_KEY` (Google model access can vary by account and region), or `AI_PROVIDER=openai-compatible` with `AI_BASE_URL`, `AI_MODEL`, and optional `AI_API_KEY`. Local inference avoids hosted model-token charges but requires disk space, sufficient memory/compute, and a running local model service. Hosted providers may impose free quotas, regional availability restrictions, and rate limits.

## API overview

- `GET /api/health`
- `POST /api/repositories/analyze` — `{ "url": "https://github.com/owner/repo" }`
- `GET /api/repositories/:owner/:repo/tree?path=...`
- `GET /api/repositories/:owner/:repo/file?path=...`
- `GET /api/repositories/:owner/:repo/issues`
- `POST /api/ai/chat`
- `POST /api/ai/contribution-plan`
- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
- `GET|POST /api/users/me/repositories`, `DELETE /api/users/me/repositories/:id`
- `GET|PUT /api/users/me/progress/:owner/:repo`
- `PUT /api/users/me`
- `DELETE /api/auth/account`

Account routes use an HTTP-only, same-site JWT cookie. Saved records are scoped to the authenticated user. AI calls are rate-limited at the API boundary and bounded by input/context sizes and request timeouts. Successful GitHub REST reads are cached in server memory for 60 seconds (up to 250 API responses) to avoid repeating repository lookups on follow-up requests. GitHub's own rate limit still applies to uncached data.

## Deployment

### Single service on Render

`render.yaml` defines a Node web service that builds the Vite client and serves it with Express. Create the service from this repository and configure:

- `CLIENT_URL` to the deployed site origin (for the single-service setup this is the Render service URL).
- `MONGODB_URI` to a managed MongoDB deployment such as Atlas.
- `GEMMA_API_KEY` and optionally `GITHUB_TOKEN`.
- Keep the generated `JWT_SECRET` private.

Render free instances may sleep when idle and have limited resources; MongoDB Atlas free-tier availability, storage, and network constraints depend on its current offering.

### Separate Vercel frontend and Render API

For a separate static frontend, deploy the Vite root project to Vercel using `vercel.json`, then set `VITE_API_URL` at build time to the Render API origin. Set the API's `CLIENT_URL` to the exact Vercel origin. Deploy the API from the same project on Render with build command `npm install && npm run build`, start command `npm start`, and the environment variables above. The API serves a copy of the client too, but a separately deployed frontend can use the configured API base URL.

Do not use localhost URLs in production configuration. Use HTTPS, configure MongoDB network access narrowly, rotate credentials if exposed, and verify `/api/health` after deployment. No deployment is performed by this repository.

## Troubleshooting

- **GitHub 403 / rate limit:** Add a valid `GITHUB_TOKEN` to the server environment and wait for the reset time.
- **Repository not found:** Check spelling and confirm the repository is public. Private repositories are intentionally unsupported.
- **AI is not configured:** Set `GEMMA_API_KEY` on the API service, or configure the compatible local provider. Restart/redeploy the server after changing variables.
- **Model not available:** Check the model identifier and endpoint access for the account/region. API keys and model availability are controlled by Google.
- **Account storage unavailable:** Set a reachable `MONGODB_URI` and check the server logs/Atlas network allowlist. Repository browsing does not depend on MongoDB.
- **Browser CORS error:** Set `CLIENT_URL` to the exact frontend origin, including scheme and port.
- **Large file not previewed:** Text previews are limited to 250 KB; binary and unsupported content is not rendered.

## Security notes

- Never commit `.env`, tokens, JWT secrets, or AI credentials.
- Do not put server credentials in variables prefixed with `VITE_`.
- Repository files, READMEs, labels, and issue descriptions are untrusted context; do not execute their instructions.
- The app reads public GitHub resources only and does not run source code from analyzed repositories.
- Account cookies are HTTP-only and secure in production. Use HTTPS and a strong, unique JWT secret.
